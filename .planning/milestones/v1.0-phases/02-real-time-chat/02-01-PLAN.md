  <action>
Create `FRONTEND/supabase/migrations/002_chat_schema.sql` with the following tables and policies, following the exact patterns from 001_initial_schema.sql:

1. **messages table:**
   - `id` UUID DEFAULT gen_random_uuid() PRIMARY KEY
   - `pair_id` UUID REFERENCES pairs(id) NOT NULL — the conversation this message belongs to
   - `sender_id` UUID REFERENCES auth.users NOT NULL — who sent it
   - `content` TEXT NOT NULL — message text
   - `reply_to` UUID REFERENCES messages(id) — nullable, for quoted replies (per D-14)
   - `created_at` TIMESTAMP WITH TIME ZONE DEFAULT NOW()
   - `updated_at` TIMESTAMP WITH TIME ZONE DEFAULT NOW()
   - `deleted` BOOLEAN DEFAULT FALSE — soft delete flag
   - `deleted_for_everyone` BOOLEAN DEFAULT FALSE — per D-30, D-32
   - CHECK constraint: char_length(content) >= 1 (prevent empty messages — specless probe: empty edge)
   - Index on (pair_id, created_at) for efficient message loading

2. **reactions table:**
   - `id` UUID DEFAULT gen_random_uuid() PRIMARY KEY
   - `message_id` UUID REFERENCES messages(id) ON DELETE CASCADE NOT NULL
   - `user_id` UUID REFERENCES auth.users NOT NULL
   - `emoji` TEXT NOT NULL
   - `created_at` TIMESTAMP WITH TIME ZONE DEFAULT NOW()
   - UNIQUE constraint on (message_id, user_id, emoji) — one reaction per emoji per user per message

3. **typing_status table:**
   - `id` UUID DEFAULT gen_random_uuid() PRIMARY KEY
   - `pair_id` UUID REFERENCES pairs(id) NOT NULL
   - `user_id` UUID REFERENCES auth.users NOT NULL
   - `is_typing` BOOLEAN DEFAULT FALSE
   - `updated_at` TIMESTAMP WITH TIME ZONE DEFAULT NOW()
   - UNIQUE constraint on (pair_id, user_id) — one typing record per user per pair

4. **RLS policies for messages:**
   - Enable RLS on messages table
   - SELECT: Users can view messages where pair_id matches a pair they belong to (auth.uid() = user_one OR auth.uid() = user_two from pairs table)
   - INSERT: Users can insert messages where pair_id matches their pair and sender_id = auth.uid()
   - UPDATE: Users can update messages where sender_id = auth.uid() (for own messages — edit/delete)
   - DELETE: Users can delete messages where sender_id = auth.uid()

5. **RLS policies for reactions:**
   - Enable RLS on reactions table
   - SELECT: Users can view reactions on messages in their pair (join through messages to pairs)
   - INSERT: Users can insert reactions where user_id = auth.uid() and the message belongs to their pair
   - DELETE: Users can delete their own reactions (user_id = auth.uid())

6. **RLS policies for typing_status:**
   - Enable RLS on typing_status table
   - SELECT: Users can view typing status for their pair
   - INSERT/UPDATE: Users can update their own typing status (user_id = auth.uid())

7. **Realtime publication:**
   - ALTER PUBLICATION supabase_realtime ADD TABLE messages
   - ALTER PUBLICATION supabase_realtime ADD TABLE reactions
   - ALTER PUBLICATION supabase_realtime ADD TABLE typing_status

8. **RPC functions:**
   - `mark_messages_read(p_pair_id UUID, p_user_id UUID)` — Updates a last_read timestamp or marks messages as read for the partner. Simple approach: create a `pair_reads` table or use the existing pairs table with a `last_read_at` column. For v1, simplest is: UPDATE messages SET read_at = NOW() WHERE pair_id = p_pair_id AND sender_id != p_user_id AND read_at IS NULL. Add `read_at` TIMESTAMP column to messages table.
   - Actually, simpler: add `read_at` TIMESTAMP WITH TIME ZONE nullable column to messages. The RPC sets read_at = NOW() for all unread messages in a pair where sender != the reading user.

Do NOT hand-roll encryption or auth — use Supabase RLS per AGENTS.md architecture rules.

Create `FRONTEND/src/stores/chatStore.js` as a Zustand store following the exact pattern from authStore.js. This store manages all chat state and Supabase Realtime integration.

**State shape:**
- `messages: []` — array of message objects, sorted by created_at ascending
- `loading: boolean` — initial load state
- `sending: boolean` — send in progress
- `error: string | null` — error message
- `partnerTyping: boolean` — whether partner is currently typing
- `isAtBottom: boolean` — scroll position tracking for auto-scroll logic
- `offlineQueue: []` — messages queued when offline
- `pairId: string | null` — current pair ID
- `subscription: object | null` — Supabase Realtime channel reference

**Actions:**

1. `initializeChat(pairId)` — Called when ChatView mounts:
   - Set pairId in state
   - Fetch all messages for this pair: `supabase.from('messages').select('*, reactions(*), profiles!sender_id(display_name, avatar_url)').eq('pair_id', pairId).order('created_at', { ascending: true })`
   - Mark unread messages as read via `supabase.rpc('mark_messages_read', { p_pair_id: pairId, p_user_id: user.id })`
   - Subscribe to Realtime changes on messages table filtered by pair_id (per D-01)
   - Subscribe to Realtime changes on reactions table
   - Subscribe to Realtime changes on typing_status table for partner
   - Set loading = false

2. `sendMessage(content, replyTo = null)` — Per D-01, D-02:
   - If offline (navigator.onLine === false), add to offlineQueue with a temp ID and pending status
   - If online, insert into messages table: `supabase.from('messages').insert({ pair_id, sender_id: user.id, content, reply_to: replyTo })`
   - Optimistically add message to messages array immediately (with temp ID that gets replaced on Realtime confirm)
   - Handle error: set error state, keep message in queue for retry

3. `syncOfflineQueue()` — Per D-02:
   - Called when online status changes to true
   - Iterate offlineQueue, insert each message
   - Remove synced messages from queue
   - Show loading indicator during sync

4. `deleteMessage(messageId, forEveryone)` — Per D-30, D-31, D-32:
   - If forEveryone: UPDATE messages SET deleted = true, deleted_for_everyone = true where id = messageId and sender_id = user.id
   - If forSelf: UPDATE messages SET deleted = true where id = messageId and sender_id = user.id
   - Optimistically update local state

5. `addReaction(messageId, emoji)` — Per D-18 through D-22:
   - Check if user already has this reaction on this message
   - If yes: DELETE the reaction (toggle off)
   - If no: INSERT into reactions (message_id, user_id, emoji)

6. `removeReaction(reactionId)`:
   - DELETE from reactions where id = reactionId

7. `setTyping(isTyping)` — Per D-04:
   - UPSERT into typing_status: { pair_id, user_id, is_typing }
   - If isTyping = true, set a 3-second timeout to auto-set isTyping = false (debounce)

8. `cleanup()` — Called on unmount:
   - Unsubscribe from all Realtime channels
   - Clear intervals/timeouts

**Realtime subscription pattern:**

```js
  .channel(`chat:${pairId}`)
  .on('postgres_changes', {
    event: '*',

  }, (payload) => {
    // Handle INSERT, UPDATE based on payload.eventType

  .on('postgres_changes', {
    event: '*',

    // Update reactions for the affected message
  })

    event: '*',
    schema: 'public',

    // Update partnerTyping state
  })

```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Supabase | Messages cross from untrusted client to Supabase DB; RLS enforces pair-scoped access |
| client → Supabase Realtime | Realtime events arrive from Supabase; client must validate event shape before state update |
| offline queue → Supabase | Queued messages sync when online; must prevent duplicate sends |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | messages table | high | mitigate | RLS policies ensure sender_id = auth.uid() on INSERT; content CHECK prevents empty |
| T-02-02 | Info Disclosure | messages table | medium | mitigate | RLS restricts SELECT to pair members only; no cross-pair data leakage |
| T-02-03 | Tampering | reactions table | medium | mitigate | RLS ensures user_id = auth.uid() on INSERT; UNIQUE constraint prevents duplicates |
| T-02-04 | Denial of Service | Realtime subscription | low | accept | Supabase handles connection limits; excessive subscriptions degrade performance but don't compromise security |
| T-02-05 | Tampering | offline queue | medium | mitigate | Messages queued locally use temp IDs; on sync, server assigns real IDs; dedup via content hash |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] |
</threat_model>
