**Step 1: Supabase Migration — Extend messages table and create storage bucket**

Apply the following migration via Supabase MCP `apply_migration` or SQL editor:

```sql
-- Extend messages table for media support
ALTER TABLE messages
  ADD COLUMN IF NOT EXISTS message_type TEXT DEFAULT 'text' CHECK (message_type IN ('text', 'voice', 'image')),
  ADD COLUMN IF NOT EXISTS media_url TEXT,
  ADD COLUMN IF NOT EXISTS media_duration INTEGER,
  ADD COLUMN IF NOT EXISTS media_width INTEGER,
  ADD COLUMN IF NOT EXISTS media_height INTEGER;

-- Drop the existing content_not_empty constraint and replace with flexible check
ALTER TABLE messages DROP CONSTRAINT IF EXISTS content_not_empty;
ALTER TABLE messages ADD CONSTRAINT content_or_media CHECK (
  char_length(content) >= 1 OR media_url IS NOT NULL
);
```

Create the `chat-media` storage bucket:
```sql
-- Create chat-media storage bucket (public for CDN access, RLS handles pair scoping)
INSERT INTO storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
VALUES ('chat-media', 'chat-media', true, 31457280, ARRAY['audio/webm', 'audio/ogg', 'audio/mp4', 'audio/wav', 'image/jpeg', 'image/png', 'image/webp'])
ON CONFLICT (id) DO NOTHING;
```

Create RLS policies for chat-media bucket:
```sql
-- Allow authenticated users to upload to their pair's folder
CREATE POLICY "Pair members can upload chat media"
ON storage.objects FOR INSERT TO authenticated
WITH CHECK (
  bucket_id = 'chat-media'
  AND (storage.foldername(name))[1] IN (
    SELECT pair_id::text FROM pairs WHERE user_one = auth.uid() OR user_two = auth.uid()
  )
);

-- Allow authenticated users to read their pair's media
CREATE POLICY "Pair members can read chat media"
ON storage.objects FOR SELECT TO authenticated
USING (
  bucket_id = 'chat-media'
  AND (storage.foldername(name))[1] IN (
    SELECT pair_id::text FROM pairs WHERE user_one = auth.uid() OR user_two = auth.uid()
  )
);

-- Allow authenticated users to delete their own uploaded media
CREATE POLICY "Pair members can delete their chat media"
ON storage.objects FOR DELETE TO authenticated
USING (
  bucket_id = 'chat-media'
  AND (storage.foldername(name))[1] IN (
    SELECT pair_id::text FROM pairs WHERE user_one = auth.uid() OR user_two = auth.uid()
  )
);
```

**Step 3: Create mediaRecorder.js utility**

Create `FRONTEND/src/shared/lib/mediaRecorder.js`. This module exports a `useVoiceRecorder` custom hook that:

- Uses `navigator.mediaDevices.getUserMedia({ audio: true })` to get microphone stream
- Creates a `MediaRecorder` with `mimeType: 'audio/webm;codecs=opus'` (per D-06). If WebM/Opus is not supported (`MediaRecorder.isTypeSupported` returns false), fall back to `'audio/webm'` then `'audio/mp4'`
- Creates `AudioContext` + `AnalyserNode` (fftSize=256) connected to the media stream source for live waveform data
- Exposes: `isRecording`, `duration`, `waveformData` (Uint8Array from `getByteTimeDomainData`), `startRecording()`, `stopRecording()` (returns Promise&lt;Blob&gt;), `cancelRecording()`
- `stopRecording()` collects chunks from `ondataavailable`, creates Blob with type matching the mimeType, then stops all tracks via `stream.getTracks().forEach(t => t.stop())` (critical — Pitfall 2)
- `cancelRecording()` stops MediaRecorder without resolving the blob, cleans up tracks, resets state
- Duration timer uses `setInterval(1000)` and auto-stops at 300 seconds (5 minutes per D-07)
- Waveform updates use `requestAnimationFrame` calling `analyser.getByteTimeDomainData(dataArray)` and setting state with a new Uint8Array copy
- Cleanup on unmount: stops tracks, clears intervals, cancels animation frames
- IMPORTANT: Always stop MediaStream tracks in both `onstop` handler AND useEffect cleanup to prevent persistent microphone indicator (Pitfall 2)

**Step 4: Create imageCompress.js utility**

Create `FRONTEND/src/shared/lib/imageCompress.js`. This module exports an async `compressImage(file, options)` function that:

- Accepts `file` (File object) and optional `options` with `maxWidth` (default 1920), `quality` (default 0.8), `outputType` (default 'image/jpeg')
- Creates an `Image` element, loads the file via `URL.createObjectURL`
- If image width exceeds maxWidth, scales height proportionally (per D-10: client-side compression)
- Draws to an offscreen `<canvas>`, calls `canvas.toBlob(resolve, outputType, quality)`
- Returns `{ blob, width, height, originalSize, compressedSize }` — revokes the object URL after loading
- Always strips EXIF data (Canvas API does this naturally — privacy benefit)

The hook and utility should be written as standalone modules with clear JSDoc comments. Do NOT place code fences inside the action — this is implementation guidance. The executor writes the actual code.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Supabase Storage | Media file uploads cross from untrusted browser to cloud storage |
| Client → Supabase Database | Message metadata inserts (message_type, media_url) cross from untrusted browser |
| User → Browser API | MediaRecorder and file picker require user permission grants |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | Media upload (chat-media bucket) | high | mitigate | Validate MIME type client-side + bucket `allowed_mime_types` constraint + RLS policies check pair membership |
