- `id UUID DEFAULT gen_random_uuid() PRIMARY KEY`
- `pair_id UUID NOT NULL REFERENCES pairs(id) ON DELETE CASCADE`

**Table 2: agenda_events** (per CONTEXT.md decisions D-08, D-09, D-10, D-11)
- `id UUID DEFAULT gen_random_uuid() PRIMARY KEY`
- `pair_id UUID NOT NULL REFERENCES pairs(id) ON DELETE CASCADE`
- `user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE`
- `title TEXT NOT NULL`
- `description TEXT DEFAULT ''`
- `event_date TIMESTAMPTZ NOT NULL`
- `category TEXT DEFAULT 'Outro'` (D-09: one of Noite de Date, Consulta, Aniversário, Viagem, Outro)
- `reminder TEXT` (D-11: nullable — one of '1h', '1d', '1w' or null)
- `created_at TIMESTAMPTZ DEFAULT now()`
- `updated_at TIMESTAMPTZ DEFAULT now()`
- RLS policies: SELECT (pair members), INSERT (pair members, own user_id), UPDATE (pair members), DELETE (pair members)
- Index: `idx_agenda_events_pair_date ON agenda_events (pair_id, event_date ASC)`

All RLS policies use the same pattern from album_photos: `pair_id IN (SELECT id FROM pairs WHERE user_one = auth.uid() OR user_two = auth.uid())`.

Create two Zustand stores following the exact pattern from albumStore.js.

**notesStore.js** — for shared_notes table:
- State: `notes[]`, `loading`, `error`, `pairId`, `subscription`
- `initializeNotes(pairId)`: fetch all notes ordered by created_at DESC, subscribe to Realtime INSERT/UPDATE/DELETE on shared_notes filtered by pair_id. Use `alreadyPresent` check before adding optimistic inserts (per pitfall 2 in RESEARCH.md).
- `createNote(title, body)`: optimistic insert with temp ID, Supabase insert, replace temp with real record on success. Return `{ success, error }`.
- `updateNote(noteId, title, body)`: optimistic update in local state, Supabase update. Rollback on error.
- `deleteNote(noteId)`: optimistic removal, Supabase delete. Rollback on error.
- `cleanup()`: remove channel, reset state.

**agendaStore.js** — for agenda_events table:
- State: `events[]`, `loading`, `error`, `pairId`, `subscription`
- `initializeAgenda(pairId)`: fetch all events ordered by event_date ASC, subscribe to Realtime INSERT/UPDATE/DELETE on agenda_events filtered by pair_id.
- `createEvent({ title, description, event_date, category, reminder })`: optimistic insert, Supabase insert with `.select().single()`. Return `{ success, error }`.
- `updateEvent(eventId, updates)`: optimistic update, Supabase update. Rollback on error.
- `deleteEvent(eventId)`: optimistic removal, Supabase delete. Rollback on error.
- `getEventsForDate(date)`: helper that filters events array by date (using date-fns isSameDay). Used by CalendarGrid.
- `cleanup()`: remove channel, reset state.

Both stores must:
- Import `create` from 'zustand', `supabase` from '../shared/lib/supabase', `useAuthStore` from './authStore'
- Use `useAuthStore.getState()` to get current user
- Guard on `user && pairId` before any operation
- Skip re-initialization if `pairId` matches and subscription exists
- Subscribe to `postgres_changes` with filter `pair_id=eq.${pairId}`

Follow the optimistic update pattern from albumStore.js: set optimistic state first, then Supabase call, then replace with real data on success, rollback on error.
