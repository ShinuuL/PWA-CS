# Plan 06-04 — UI Audit Gap Closure

## Goal
Fix 2 BLOCKER issues from the Phase 6 UI audit (16/24 score):
1. Header partner avatar tap is non-functional
2. ChatView chat header shows current user's avatar instead of partner's

## Tasks

### Task 1: Wire PartnerProfileModal into Header.jsx

**Files:** `FRONTEND/src/shared/components/Header.jsx`

**What:**
- Import `useState` and `PartnerProfileModal` from `features/profile/PartnerProfileModal`
- Add `const [showPartnerProfile, setShowPartnerProfile] = useState(false)` state
- Replace the empty onClick placeholder on the partner avatar (line 63) with `onClick={() => setShowPartnerProfile(true)}`
- Render `<PartnerProfileModal isOpen={showPartnerProfile} onClose={() => setShowPartnerProfile(false)} />` inside Header component
- Follow the same pattern used in Drawer.jsx (lines 114, 159-162)

**Why:** Users tapping the partner avatar in the header see nothing happen. The onClick is a no-op comment. The Drawer correctly wires PartnerProfileModal but Header does not.

**Reference:** Drawer.jsx:114, 159-162 for the exact pattern

### Task 2: Fix ChatView header to show partner avatar/name

**Files:** `FRONTEND/src/features/chat/ChatView.jsx`

**What:**
- The chat header (lines 542-547) currently renders `user?.user_metadata?.avatar_url` (current user)
- Replace with partner profile data fetched from the pair
- Use the same `pairData` that Header.jsx already fetches via `usePair()` or equivalent
- Fetch partner profile from `profiles` table using `pairData.partner_id` or `pairData.user_id`
- Render partner's avatar_url and display_name in the chat header
- Keep current user's info as fallback if partner data is unavailable

**Why:** The chat header displays the current user's avatar and name instead of the partner's. Plan 3 Task 1 Part C explicitly stated this should use partner profile data but it was never applied.

**Reference:** Header.jsx lines 30-50 for how partner profile is fetched via usePair()

### Task 3: Fix profile.css hardcoded colors

**Files:** `FRONTEND/src/features/profile/profile.css`

**What:**
- Line 49: Change `color: #22c55e` → `var(--color-online)`
- Line 115: Change `color: #22c55e` → `var(--color-online)`

**Why:** Minor color token consistency fix from UI audit Pillar 3.
