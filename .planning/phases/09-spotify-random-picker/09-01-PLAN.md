  <behavior>
    Deno-based Edge Function that handles two actions:
    1. "exchange" — Receives authorization code + redirect_uri from client, exchanges for tokens via Spotify API, encrypts tokens via pgcrypto, upserts into spotify_config, returns access_token + expires_in
    2. "refresh" — Receives pair_id from client, fetches encrypted refresh_token, decrypts, refreshes via Spotify API, re-encrypts new tokens, updates spotify_config, returns new access_token + expires_in
    On invalid_grant during refresh: deletes spotify_config row, returns 401 with { error: "reconnect_required" }
    Reads SPOTIFY_CLIENT_ID, SPOTIFY_CLIENT_SECRET, SPOTIFY_TOKEN_ENCRYPTION_KEY from Deno.env
    Uses service_role key for DB access (bypasses RLS)
    Returns CORS headers on all responses
    Handles OPTIONS preflight
  </behavior>
  <action>
    1. Create FRONTEND/supabase/functions/spotify-auth/index.ts
    2. Import serve from Deno std and createClient from @supabase/supabase-js via esm.sh
    3. Define corsHeaders object matching send-push-notification pattern
    4. Handle OPTIONS method return
    5. Parse request body for action, code, redirect_uri, pair_id
    6. Create Supabase client with service_role key
    7. For action="exchange":
       a. POST to https://accounts.spotify.com/api/token with grant_type=authorization_code, code, redirect_uri, client_id, client_secret
       b. On success: extract access_token, refresh_token, expires_in
       c. Calculate token_expires_at = now + expires_in seconds
       d. Encrypt tokens via supabase.rpc('encrypt_token', { p_token, p_key: SPOTIFY_TOKEN_ENCRYPTION_KEY })
       e. Upsert into spotify_config with pair_id, encrypted tokens, playlist_id (empty initially)
       f. Return { access_token, expires_in } to client
    8. For action="refresh":
       a. Fetch spotify_config row for pair_id
       b. Decrypt refresh_token via supabase.rpc('decrypt_token', { p_encrypted, p_key })
       c. POST to https://accounts.spotify.com/api/token with grant_type=refresh_token, refresh_token, client_id, client_secret
       d. If error === "invalid_grant": delete spotify_config row, return 401
       e. Otherwise: encrypt new tokens, update spotify_config, return { access_token, expires_in }
    9. Return 500 on unexpected errors with error message
  </action>

    Deploy: cd FRONTEND && npx supabase functions deploy spotify-auth
    Set secrets: npx supabase secrets set SPOTIFY_CLIENT_ID=xxx SPOTIFY_CLIENT_SECRET=xxx SPOTIFY_TOKEN_ENCRYPTION_KEY=xxx
    Manual test: Invoke with action="exchange" and a valid auth code from Spotify OAuth
  </verify>
  <accessance_criteria>
    - Edge Function handles OPTIONS preflight with CORS headers
    - exchange action: receives code, exchanges for tokens, encrypts, stores in DB, returns access_token
    - refresh action: decrypts refresh_token, refreshes via Spotify API, re-encrypts, updates DB, returns new access_token

<threat_model>

| STRIDE | Threat | Mitigation |
|--------|--------|------------|
| Spoofing | OAuth code interception | PKCE (S256 code_challenge) prevents code reuse; state parameter prevents CSRF |
| Tampering | XSS stealing access token from memory | Token held in Zustand (in-memory), not localStorage; no dangerouslySetInnerHTML |
| Repudiation | Unauthorized playlist modification | Edge Functions verify user owns pair via Supabase JWT; RLS enforces pair_id |
| Information Disclosure | Token theft via DB breach | pgcrypto AES-256 encryption; tokens useless without encryption key stored in Edge Function env |
| Denial of Service | Rate limiting on Spotify API | Exponential backoff; 300ms debounce on search; respect 429 responses |
| Elevation of Privilege | Refresh token abuse after expiry | 6-month expiry enforced; invalid_grant handling clears tokens and prompts reauth |

</threat_model>
