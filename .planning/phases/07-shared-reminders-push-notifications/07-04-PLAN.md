## Objective

Complete push notification infrastructure: custom service worker with push event handler, client-side subscription management, Supabase Edge Functions for reminder and chat push delivery, pg_cron scheduling, chatStore background push integration, and Settings push toggle.

Purpose: Reliable push delivery — the core differentiator. Both reminder and chat push notifications work on Android and iOS (installed PWA).

Output: Custom service worker, push subscription utility, Edge Functions, pg_cron migration, chatStore modifications, SettingsPage push toggle.

- **Action:**

  **2a. Reminder Push Edge Function (`supabase/functions/send-push-notification/index.ts`):**
  Deno Edge Function that:
  1. Receives POST with `{ reminder_id, pair_id }` body
  2. Loads VAPID private key from Deno.env (stored in Supabase Vault per research)
  3. Fetches all push_subscriptions where `pair_id` matches the reminder's pair_id
  4. For each subscription: send push notification via `@negrel/webpush` library
     - Title: `"{Creator name} te lembra:"` (per D-19) — fetch creator display_name from profiles table
     - Body: `"{reminder title}"` (per D-19)
     - Tag: `"couplespace-reminder-{reminder_id}"` (per D-21 — unique per reminder)
     - URL: `"/agenda"` (per D-20)
  5. After sending: Update `shared_reminders.status` to `'sent'` where `id = reminder_id`
  6. On 410 error: Remove expired subscription from `push_subscriptions` (per research subscription cleanup)
  7. On other errors: Mark reminder status as `'pending_send'` (per D-07 retry strategy)
  8. Return 200 on success

  **2b. Chat Push Edge Function (`supabase/functions/send-chat-push/index.ts`):**
  Deno Edge Function that:
  1. Receives POST with `{ recipient_id, sender_name, message_text }` body
  2. Fetches all push_subscriptions where `user_id = recipient_id`
  3. For each subscription: send push notification
     - Title: `"{Sender name}"` (per D-26)
     - Body: `"{message text}"` truncated to ~50 chars (per D-26)
     - Tag: `"couplespace-chat"` (per D-26)
     - URL: `"/chat"`
  4. On 410: Remove expired subscription
  5. Return 200 on success

  **2c. pg_cron Migration (`20260729_pg_cron_send_reminders.sql`):**
  SQL migration that:
  1. Enables pg_cron and pg_net extensions (if not already)
  2. Creates cron job `'send-due-reminders'` running every minute (`'* * * * *'`)
  3. Job queries `shared_reminders` where `reminder_at <= NOW() AND completed_at IS NULL AND status = 'pending'`
  4. For each due reminder: calls `send-push-notification` Edge Function via `net.http_post()`
  5. Uses Vault secrets for project URL and anon key

  **2d. ChatStore Background Push Integration (per D-25, D-26):**
  Modify `chatStore.js` Realtime subscription handler (INSERT event, lines 108-133):
  1. After the existing `if (!state.isInChat)` block (line 124), add foreground/background detection:
     ```javascript
     const isAppInForeground = document.visibilityState === 'visible'
     ```
  2. If app is NOT in foreground AND message is from partner (`newMsg.sender_id !== user.id`):
     - Call Edge Function `send-chat-push` with `{ recipient_id: user.id, sender_name: newMsg.profiles?.display_name, message_text: newMsg.content?.substring(0, 50) }`
     - This sends push via server (not client-side Notification API)
  3. If app IS in foreground: Use existing `showNotification()` (in-app toast) — no double notification (per D-25)
  4. The existing `showNotification` call at line 127-131 remains for in-app notifications when app is open

  Important: The `isInChat` flag already prevents notifications when user is in chat view. The new logic adds background detection for push vs in-app.
