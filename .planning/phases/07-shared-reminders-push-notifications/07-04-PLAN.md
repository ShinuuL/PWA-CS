## Objective

Client-side push notification infrastructure: custom service worker with push event handler, client-side subscription management, and Settings push toggle.

Purpose: Client half of push delivery — handles receiving notifications and managing subscription state. Server-side scheduling (Edge Functions + pg_cron) is in Plan 05.

Output: Custom service worker, push subscription utility, SettingsPage push toggle.

## Tasks

### Task 1: Custom Service Worker + Client Push Subscription Utility + Settings Toggle
- **Type:** feature
- **Files:** FRONTEND/src/sw.js, FRONTEND/vite.config.js, FRONTEND/src/shared/lib/pushSubscription.js, FRONTEND/src/features/settings/SettingsPage.jsx, FRONTEND/src/features/settings/settings.css
- **read_first:**
  - FRONTEND/vite.config.js (current VitePWA config — workbox settings, registerType, manifest)
  - FRONTEND/src/stores/chatStore.js (showNotification at line 587-601, requestNotificationPermission at line 578-583, notificationPermission state)
  - FRONTEND/src/features/settings/SettingsPage.jsx (current structure — Account, Relationship, Session sections)
  - FRONTEND/src/features/settings/settings.css (existing styles)
  - FRONTEND/src/features/agenda/AgendaPage.jsx (for deep-link URL understanding)
- **Action:**

  **1a. Custom Service Worker (`src/sw.js`):**
  Create a custom service worker that extends workbox with push event handling. The file must:
  - Import and call workbox precaching: `import { precacheAndRoute } from 'workbox-precaching'; precacheAndRoute(self.__WB_MANIFEST)`
  - Add `push` event listener (per REMN-08): Parse `event.data?.json()`, call `self.registration.showNotification()` with title, body, icon (`/icons/icon-192.png`), badge (`/icons/icon-192.png`), data.url (for deep-linking), tag, renotify: true
  - Add `notificationclick` event listener (per D-20): Close notification, deep-link to URL from `event.notification.data.url`. Match existing window client or open new window. For reminders: deep-link to `/agenda` (Lembretes tab will be handled client-side). For chat: deep-link to `/chat`.
  - Notification data format:
    - Reminder: `{ title: "{Creator} te lembra:", body: "{reminder title}", url: "/agenda", tag: "couplespace-reminder-{id}" }` (per D-19, D-21)
    - Chat: `{ title: "{Sender name}", body: "{message text}", url: "/chat", tag: "couplespace-chat" }` (per D-26)
  - Each notification gets its own push event (per D-21 — no grouping)
  - Use default system notification sound only — no custom audio (per D-22)

  **1b. Update `vite.config.js`:**
  - Add `swSrc: 'src/sw.js'` to VitePWA config (tells vite-plugin-pwa to use custom SW instead of generated one)
  - Keep existing workbox config (globPatterns, navigateFallback, runtimeCaching)
  - The custom SW will be built by vite-plugin-pwa with workbox injected

  **1c. Push Subscription Utility (`src/shared/lib/pushSubscription.js`):**
  Create utility functions:
  - `urlBase64ToUint8Array(base64String)`: Convert VAPID public key to Uint8Array for subscription
  - `subscribeToPush(vapidPublicKey)`: Get service worker registration, call `registration.pushManager.subscribe()` with userVisibleOnly and applicationServerKey. Store subscription in `push_subscriptions` table via Supabase client. Return subscription or null.
  - `unsubscribeFromPush()`: Get current subscription, call `subscription.unsubscribe()`, remove from `push_subscriptions` table.
  - `getPushSubscription()`: Return current push subscription if exists.
  - `isPushSupported()`: Check if `PushManager` is available in window and service worker is registered.
  - `isIOSStandalone()`: Check `/iphone|ipad/i.test(navigator.userAgent)` AND `window.matchMedia('(display-mode: standalone)').matches` — per research iOS limitation
  - Export VAPID public key from env: `import.meta.env.VITE_VAPID_PUBLIC_KEY` (will be set in .env.local)
  - Handle iOS Safari: If iOS and not standalone, return false from `isPushSupported()` and show install prompt message

  **1d. SettingsPage Push Toggle (per D-24):**
  Add a "Notificações" section to SettingsPage between "Account" and "Relationship":
  - Show current permission status: "Permitido" (green), "Negado" (red), "Não solicitado" (gray)
  - Toggle switch: When ON, request permission if not granted. When OFF, show message "Para desativar, altere nas configurações do navegador"
  - If permission is 'denied', show explanation: "Notificações bloqueadas. Permita nas configurações do navegador."
  - If push not supported (iOS not standalone): Show message "Instale o CoupleSpace na tela inicial para receber notificações"
  - Use existing settings section styling pattern

  CSS additions to `settings.css`:
  - `.settings-section-toggle` flex row, justify between, align center
  - `.settings-toggle-switch` custom toggle (44x24px, rounded, background changes with state)
  - `.settings-toggle-status` small text, color varies with permission state

  Manual: Register service worker via browser DevTools → Application → Service Workers. Verify SW is active. Check push subscription state. Navigate to Settings → verify Notificações section shows correct permission status. Toggle permission request flow.
