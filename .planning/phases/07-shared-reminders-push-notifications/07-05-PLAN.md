- **Action:**

  **1a. Reminder Push Edge Function (`supabase/functions/send-push-notification/index.ts`):**
  Deno Edge Function that:
  1. Receives POST with `{ reminder_id, pair_id }` body
  2. Loads VAPID private key from Deno.env (stored in Supabase Vault per research)
  3. Fetches all push_subscriptions where `pair_id` matches the reminder's pair_id
  4. For each subscription: send push notification via `@negrel/webpush` library
     - Title: `"{Creator name} te lembra:"` (per D-19) — fetch creator display_name from profiles table
     - Body: `"{reminder title}"` (per D-19)
     - Tag: `"couplespace-reminder-{reminder_id}"` (per D-21 — unique per reminder)
     - URL: `"/agenda"` (per D-20)
  5. After sending: Update `shared_reminders.status` to `'sent'` where `id = reminder_id`
  6. On 410 error: Remove expired subscription from `push_subscriptions` (per research subscription cleanup)
  7. On other errors: Mark reminder status as `'pending_send'` (per D-07 retry strategy)
  8. Return 200 on success

  **1b. Chat Push Edge Function (`supabase/functions/send-chat-push/index.ts`):**
  Deno Edge Function that:
  1. Receives POST with `{ recipient_id, sender_name, message_text }` body
  2. Fetches all push_subscriptions where `user_id = recipient_id`
  3. For each subscription: send push notification
     - Title: `"{Sender name}"` (per D-26)
     - Body: `"{message text}"` truncated to ~50 chars (per D-26)
     - Tag: `"couplespace-chat"` (per D-26)
     - URL: `"/chat"`
  4. On 410: Remove expired subscription
  5. Return 200 on success

  **1c. pg_cron Migration (`20260729_pg_cron_send_reminders.sql`):**
  SQL migration that:
  1. Enables pg_cron and pg_net extensions (if not already)
  2. Creates cron job `'send-due-reminders'` running every minute (`'* * * * *'`)
  3. Job queries `shared_reminders` where `reminder_at <= NOW() AND completed_at IS NULL AND status = 'pending'`
  4. CORRECTED SQL — the pg_cron query must JOIN or use EXISTS to find reminders that HAVE at least one matching push subscription. The original RESEARCH.md SQL used `NOT EXISTS` which is inverted. Correct logic:
     ```sql
     SELECT net.http_post(
       url := (SELECT vault.secret('project_url')) || '/functions/v1/send-push-notification',
       headers := jsonb_build_object(
         'Content-Type', 'application/json',
         'Authorization', 'Bearer ' || (SELECT vault.secret('publishable_key'))
       ),
       body := jsonb_build_object(
         'reminder_id', sr.id,
         'pair_id', sr.pair_id,
         'title', sr.title,
         'created_by', sr.created_by
       )
     )
     FROM shared_reminders sr
     WHERE sr.reminder_at <= NOW()
       AND sr.completed_at IS NULL
       AND sr.status = 'pending'
       AND EXISTS (
         SELECT 1 FROM push_subscriptions ps
         WHERE ps.pair_id = sr.pair_id
       )
     ```
     The key correction: `EXISTS` (not `NOT EXISTS`) ensures we only fire for reminders where at least one partner has an active push subscription. Reminders with no subscriptions stay `pending` and rely on the D-08 client fallback (handled in Plan 01).
  5. Uses Vault secrets for project URL and anon key
