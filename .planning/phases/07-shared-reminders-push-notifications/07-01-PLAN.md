### Task 1: Database Migrations — Status Column + Push Subscriptions Table
- **Type:** feature
- **Files:** FRONTEND/supabase/migrations/20260729_add_status_and_push_subscriptions.sql
- **read_first:**
  - FRONTEND/supabase/migrations/20260728_create_shared_reminders_table.sql (existing table schema, RLS patterns)
- **Action:** Create a single SQL migration file that:
  1. Adds `status TEXT DEFAULT 'pending' CHECK (status IN ('pending', 'sent', 'failed', 'pending_send'))` column to `shared_reminders` (per D-07 research — tracks push delivery state)
  2. Creates `push_subscriptions` table (per D-05): id UUID PK, user_id UUID FK auth.users ON DELETE CASCADE, pair_id UUID FK pairs ON DELETE CASCADE, endpoint TEXT NOT NULL, p256dh TEXT NOT NULL, auth TEXT NOT NULL, created_at TIMESTAMPTZ DEFAULT NOW()
  3. Enables RLS on `push_subscriptions` with pair-member policies matching the exact same `EXISTS (SELECT 1 FROM pairs ...)` pattern used in the shared_reminders migration (SELECT, INSERT, DELETE for pair members)
  4. Adds an index on `push_subscriptions(endpoint)` for lookup during 410 cleanup
  5. Adds an index on `shared_reminders(pair_id, status, reminder_at)` for pg_cron query performance
  - Use Supabase SQL editor conventions. All policies use `auth.uid()` check against `pairs.user_one`/`pairs.user_two` like existing migrations.
- **Verify:**
  ```sql

  SELECT column_name FROM information_schema.columns WHERE table_name = 'shared_reminders' AND column_name = 'status';
  SELECT column_name FROM information_schema.columns WHERE table_name = 'push_subscriptions';
  SELECT schemaname, tablename, policyname FROM pg_policies WHERE tablename = 'push_subscriptions';
  ```
- **Acceptance Criteria:**
  - [ ] `shared_reminders.status` column exists with CHECK constraint for 4 values
  - [ ] `push_subscriptions` table exists with all 7 columns
  - [ ] RLS enabled on `push_subscriptions` with SELECT, INSERT, DELETE policies
  - [ ] Indexes on `push_subscriptions.endpoint` and `shared_reminders(pair_id, status, reminder_at)` exist
  - [ ] Migration file follows naming convention: `20260729_add_status_and_push_subscriptions.sql`
